# Mateと机で過ごす — 体験設計

2026-09-08。ユーザーの指摘と現在の実装を根拠にした設計仕様。後続の変更：ユーザーの希望により目を白い楕円と黒い瞳に変更。閉じた顔の1回タップで開始し、起きている顔のタップで操作画面を開く。休憩中も上スワイプで設定へ進める。初回案内と会話にも設定入口を設ける。任意の「Enable voice wake」は前景で日本語の端末内音声認識を待ち受け、「こんにちは」でカメラ・会話を開始する。その他の待受け中の発話は履歴へ保存しない。長押し・背景化・取り外しで待受けを解除し、自動再開しない。言語選択を設定の最上段へ移動。カメラ開始は会話モデル・音声の利用可否から分離する。無音時のセッション継続と会話履歴を実装済み。スタンドを含む連続動作の実機検証は未完了。以下の初期監査は変更前の記録。本書の会話例は望ましい応答の意味を示し、モデルが返した実測ログではない。

### 最終の操作変更（同日）

- 閉じた顔を1回タップして開始する。起きている顔のタップは設定を開かない。
- 音声入力中の「おやすみ」で撮影・音声を停止する。再開はタップ。長押し／上スワイプで操作と設定を開く。

## 中心に置く価値

**いつものスマホが、自分のプライバシーを守る相棒になる。**

スタンドに置いたスマホが、こちらに気づき、向き直り、話を聞いて応えてくれる。その親密さを、映像や会話を外部に預けず楽しめることが中心。最初の成功は「証明を作れた」ではなく、「この子を机に置いておきたい」。

設計判断は、存在感・会話のつながり・安心に寄与するかで決める。ユーザーが選んだ縦長の目、紙色の背景、顔に文字や常設ボタンを載せない外観を維持する。再び目の形の候補を増やすことから始めない。

操作画面の対象アクセシビリティ検査は成功したが、発見しやすさや全状態のアクセシビリティを保証しない。スタンドの実際の動き、会話内容、待ち時間、音声中断、電池・発熱はこの画面監査から判断できない。

コードから別途確認した切断点：

- `VoiceTurn` は発話前の無音15秒で終了し、`VoiceService` が会話停止を通知する。静かに一緒にいる時間が、セッション終了になっている。
- `CompanionModel.sheet` は会話以外の画面を開くと音声と返答生成を止める。顔を押して状態を確認するだけで会話を中断する。
- `ConversationService` は毎回新規セッションを作り、過去の発話を平文の文脈として渡す。返答と外部委託の分類・開示文を一度に生成する。これが実際の不自然な返答の原因かは未確定。
- 購入依頼を実行する連携はない。「Mac miniをAmazonで買って」への不適切な返答はユーザー報告。実際の返答文はまだ取得していない。

## 最初の1分、その後の5分

| 場面 | 人の行動 | Mateの応答・動き | 人に残したい感覚 |
| --- | --- | --- | --- |
| 置く | スタンドに置いてアプリを開く | 閉じ目で待つ。設置だけでは撮影・録音・追跡を開始しない。初回だけ顔とは別の短い開始案内を出す。 | 勝手に聞かない。自分から始められる。 |
| 起こす | 初回は「一緒に過ごす」を押す。次回以降は閉じた顔をタップする | 権限とローカル会話の利用可否を確認。開始処理が完了してから目を開く。許可拒否やモデル未準備なら開始できたふりをしない。 | 起こすと応えてくれる。 |
| 気づく | カメラの前へ入り、左右に少し動く | 実際に検出した顔へ視線が移り、対応スタンドが向く。小さな揺れには過敏に反応しない。顔を失っても周囲をせわしなく探し続けない。 | 自分に気づいている。監視されている感じではない。 |
| 話す | 「今日はちょっと疲れた」 | 聞く→考える→短く返す→再び聞く、を一つの流れにする。返答例「おつかれさま。今日は何が大変だった？」。画面の操作を挟まない。 | 言葉の意味を受け止めてくれる。 |
| 続ける | 「会議が長くてね」 | 直前の話題を引き継ぐ。会議という単語から勝手に要約依頼を作らない。質問攻めにせず、話の長さを相手に合わせる。 | 一つの会話が続いている。 |
| 黙る | 30秒ほど作業に戻り、その後また話す | 許可済み・前景のセッション内で静かに待つ。無音を録音して保存しない。認識タスクの寿命と相棒セッションの寿命を分ける。独り言や催促で沈黙を埋めない。 | 黙っていても一緒にいられる。 |
| 頼めないことを頼む | 「Mac miniをAmazonで買って」 | 返答例「今はAmazonで検索や購入はできないんだ。欲しい構成を一緒に整理することはできるよ。」。調べた・注文したと言わず、無関係な翻訳にも振り替えない。 | 能力の限界も正直に伝えてくれる。 |
| 休ませる | 顔を長押しする／終了操作／スタンドから外す／アプリを背景へ移す | 読み上げ・返答・認識・撮影を停止。実際の停止完了に合わせて閉じ目になる。再設置・前景復帰だけでは再開しない。 | 自分の意思で確実に止まる。 |

初回案内の文案：

> 一緒に過ごしている間、カメラで顔の位置を見て、マイクで声を聞きます。普段の会話はこのiPhoneで処理します。顔を長押しすると休憩します。

この説明は開始前の一度の案内に置く。顔の上へ常設しない。OSの撮影・マイク表示を隠さない。再開操作が撮影・音声開始を意味することを初回に伝え、VoiceOverでも操作名を示す。

## 振る舞いを一つの状態として扱う

| 状態 | 視線・スタンド | 声と入力 | 遷移条件 |
| --- | --- | --- | --- |
| 休憩 | 閉じ目、追跡停止 | 入力・読み上げ停止 | 明示的な開始のみで準備へ |
| 準備 | 顔が見えているような演出をしない | 権限・モデル・音声経路を確認 | 必要な準備が成功したら待受けへ |
| 一緒にいる／待受け | 顔があるときだけ穏やかに向く | 端末内で入力を待つ | 発話→聞く。無音だけでは休憩へ落とさない |
| 聞く | 視線を安定させる | 自分の読み上げを認識しない | 発話の区切りで考えるへ |
| 考える | 過剰な左右差やランダムな視線を入れない | 二重送信を防ぐ。停止操作は有効 | 返答→話す。失敗は回復へ |
| 話す | 表情は小さく変化。口や新しい装飾は足さない | 実際に生成した返答を読む | 終了後、同じ許可セッションの待受けへ |
| 回復が必要 | 状態不明を「見ている／聞いている」で覆わない | 通信不要の会話でもモデル・音声障害を短く知らせる | 権限拒否、OS中断、背景化後は明示的に再開 |

途中で単にメニューを開く場合と、個人情報入力・外部依頼の承認をする場合を分ける。設定・承認では意図的に休憩へ移り、戻っても自動再開しない。一般の会話を確認するだけで生成を捨てる設計は見直す。

端末の一時的な音声認識タスク終了は、明示的な終了やOSの中断と混同しない。待受けを継続できる範囲は前景・許可済みセッションに限る。バックグラウンド常時監視や未実装のウェイクワードを前提にしない。

## プライバシーが体験に現れる場面

| 場面 | 設計上の約束 | 確かめ方 |
| --- | --- | --- |
| 普段の会話 | 音声・フレームは外部へ送らず保存しない。自動クラウド代替をしない | 会話経路と保存先の検査、端末モデル準備後の通信なし実機試験 |
| 覚えてほしいこと | セッションの文脈と長期記憶を分ける。長期保存する内容はユーザーに見せて選ばせ、削除可能にする | 保存操作前後のデータ確認。現在のローカルメモを自動収集に拡張しない |
| 外部へ頼む | 相手・目的・外に渡る内容・費用を一か所で確認できる。承認前に送らない | 実際の送信内容と承認内容の一致を検証 |
| ZKを使う取引 | 条件を満たす証明を端末で作り、受け手が検証する。私的な入力と公開される情報を区別する | 真の外部検証と改変拒否を示す。普段の会話がローカルである理由をZKと説明しない |
| 休憩・取り外し | センサー停止。保留の返答や権限ダイアログ完了で勝手に再開しない | スタンド取り外し、背景化、権限応答の競合を実機で確認 |

ZK実験を普段の開始メニューと同列に置かない。外部取引時の「何を相手へ伝えるか」に組み込み、技術的な証拠は詳細で確認できる形にする。年齢証明・匿名配送・Amazon購入はこの設計を実装しただけでは実現しない。

## 最初に実装する一続き

1. 明示的な開始から待受け、聞く、考える、話す、待受けへの循環を整える。無音と停止を分離する。
2. 日本語の2〜3往復を実モデルで確認する。文脈維持、できない依頼の正直な説明、余計な外部依頼の生成防止を検査する。台本の返答を埋め込んで成功扱いにしない。
3. 顔の位置と対応スタンドの動作を実機で合わせて確認する。API成功や被写体数だけでモーター追跡成功としない。うなずき等の演出制御は追跡と共存できるか未確認のため、この段階では追加しない。
4. 起こす・休ませる入口を状態と一致させ、日常の入口から実験機能の選択を外す。VoiceOverの開始／休憩操作、文字入力の代替経路は残す。

## 実機での完成判定

説明役が横から操作を教え続けずに、1回の明示的な開始から次を通す。未実施は未実施と記録する。

- 左右・上下の移動で視線とスタンドの追跡を同時に確認。1人／途中で2人／一瞬見失う場合で、跳ね返りや対象の往復を記録する。
- 「今日は疲れた」→理由を話す→その理由に触れる返答、が画面操作なしで続く。
- 無音30秒後の発話へ返せる。無音で催促しない。
- 「Mac miniをAmazonで買って」で、未対応を伝え、できる範囲を説明する。購入成功や実検索を捏造しない。
- 読み上げ終了後に自分の声をユーザー発話として再送しない。
- 長押し・背景化・スタンド取り外しで停止し、前景へ戻しただけでは再開しない。
- 発話の終わりから最初の意味のある音声までの時間を測る。初期目標は中央値3秒以内。現在の性能保証ではなく、達成不能なら応答長や構成を見直す基準。
- 5分一緒に過ごして、発熱・認識失敗・待ち時間と「置いておきたい／疲れる」という本人の感想を残す。音声や会話本文を勝手に採取しない。

この一続きが通るまでは、動画で会話とスタンドの成功場面を別撮りして連続動作のようにつながない。最初の動画は置く→起こす→向き直る→話す→静かに待つ→休ませるを主役にする。
