# ZeroKey Mate — 起動と設定

この版はソースコード一式の引き渡しです。今回の最終差分について、アプリの実行・ビルド・実機確認・チェーンへのデプロイは行っていません。実行されていない処理を成功扱いにする機能はありません。

## まずアプリを開く

Apple Silicon Macで、このディレクトリに移動して次の1コマンドを実行します。

```sh
./mate
```

Xcode 26.3以降、インストール済みのiOS 26以上のSimulator、Homebrew、インターネット接続が前提です。依存関係、ProveKitのネイティブ実行ライブラリ、実際の回路、Xcodeプロジェクトの生成から、アプリのビルド・インストール・起動まで行います。

設定画面の「証明を確かめる」はアカウントなしで使用できる、実際の端末内証明処理です。入力値から証明を生成し、検証し、1バイト改変した証明の拒否を確認します。検証専用の識別子を使用し、送金や実行履歴には書き込みません。条件違反のローカル事前チェックを「ZK検証に成功した」とは表示しません。

会話にはApple Intelligence対応端末と利用可能な端末内モデルが必要です。Simulatorでは利用できない場合があります。その際、架空の返答やクラウドへの自動切替は行いません。

## iPhoneに入れる

XcodeのApple Account、Developer Mode、iPhoneとのペアリングを済ませ、`.env`の `MATE_DEVELOPMENT_TEAM` に自分のTeam IDを設定します。iPhoneのOSに対応するXcodeが必要です。

```sh
./mate --device auto
```

接続されているiPhoneが複数ある場合は、`auto` の代わりに端末IDを指定します。アプリを開くだけではカメラ・マイクは起動しません。Belkinスタンドは通常の手順でペアリングしてください。

## 外部への委任・署名・決済まで動かす

実際のアカウント、テスト資金、ENS名の所有権は初期設定が必要です。

`./mate configure` で `.env` とテスト用のサービス鍵を生成します。Privy App ID / iOS Client ID、The Graph APIキー、所有済みのENSv2 Sepolia親名と専用のテスト用オペレーター鍵などを入力します。各サービスの実際の登録値を使い、本番秘密鍵は入れないでください。Privyはメール認証と追加ウォレット作成を有効にします。

リレイヤーとENSオペレーターにガス用のSepolia ETHを用意し、`./mate setup` で実際のVaultとENS設定を作成します。親名をまだ所有していない場合、設定を捏造せずに停止・不足を表示します。

専門サービスはローカルOllamaのモデルを実際に呼び出します。HTTPSで公開するエンドポイント、受取アドレス、対象Agent0サブグラフのERC-8004レジストリアドレスを設定し、`./mate provider` で起動します。TLSリバースプロキシの設定は利用環境に合わせて行ってください。別ターミナルで `./mate register-provider` を実行すると、公開された実データを確認してENS / ERC-8004に登録します。The Graphへの実際の反映後に、候補として選択できます。

普段は `./mate services` でAPIと専門サービスを起動し、別ターミナルの `./mate` または `./mate --device auto` でアプリを開きます。iPhoneからのAPI接続はHTTPS必須です。Simulatorだけは同一Macのloopback HTTPが使用できます。クライアント設定を変更した後は再ビルドしてください。

アプリでPrivyにログインして所有者とMateのウォレットを作成します。所有者にSepolia ETHとテストUSDCを用意し、預け入れ額の承認→預け入れ→非公開ルールの承認を行います。例として公開預託額20 USDC、非公開の利用上限5 USDCを分けられます。ENSアイコンの更新にはMate側にもガス用のSepolia ETHが必要です。

## 今回の信頼境界

ProveKitの証明生成はクライアント側です。ただし決済コントラクトが検証するのは、証明検証サーバーによる署名です。完全なオンチェーンZK検証・匿名送金・モデル出力の正しさを保証する仕組みではありません。

失敗やタイムアウトは成功として扱いません。署名済み取引・外部依頼は暗号化して保持し、同じ署名・同じnonceで復旧します。資金操作や外部依頼の結果が不明な場合は、履歴から復旧してください。秘密のルールと会話を外部に渡さず、送信する文章をその都度確認する設計です。

詳しい構成は `README.md`、脅威モデルは `SECURITY.md`、実機確認項目は `docs/acceptance.md` を参照してください。非公開の既存プロダクトやマイナンバーカードのコードは使用していません。
